# Architecture change

1. Read existing ADR index and relevant boundaries.
2. Identify problem, alternatives, trade-offs, costs and rollback.
3. Write a sequential ADR with status: `Proposed`, `Accepted`, `Superseded` or `Rejected`.
4. Explain implications for GitHub permissions, provider neutrality, privacy, idempotency, costs and operability.
5. Add tests/acceptance criteria and link the issue. Do not claim a proposal has shipped.
6. Update architecture overview and ADR index when accepted.
