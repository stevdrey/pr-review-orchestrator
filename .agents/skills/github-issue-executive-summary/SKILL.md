# GitHub issue executive summary

Use once implementation is complete, not for planning-only issues.

Prepare an English comment on the **issue**, not a PR, with:
1. `## Executive summary`: outcome in plain terms.
2. `## Why it matters`: user or operator benefit.
3. `## Delivered`: verified capabilities, docs and actual tests.
4. `## Known limits`: unverified, deferred or non-goal areas.
5. `## Follow-up`: linked issues/PRs and rollout status.

Every metric, test count, review finding and deployment claim needs actual evidence. Obtain permission before posting when task does not explicitly authorize publication. No fabricated PR links or verification.
