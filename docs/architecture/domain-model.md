# Domain model (proposal)

Entities and aggregates are described here for implementation planning.

| Concept | Core fields | Invariants |
| --- | --- | --- |
| `Installation` | GitHub installation ID, allowed repository IDs, policy version | Every action authorized for installation and repository |
| `PullRequestIdentity` | provider, repository ID, PR number | Repository ID rather than mutable name is primary key |
| `ReviewCycle` | PR identity, head SHA, stage, provider, iteration, status | One active command per unique stage/provider/SHA |
| `Finding` | stable ID, source comment/review/thread, body reference, severity, status, reviewed SHA | Support both inline and general comments; preserve provenance |
| `FindingDisposition` | finding ID, actor, reason, evidence commit, verified status | Resolution flag alone does not confirm correctness |
| `ReviewVerdict` | head SHA, reviewer, confidence/evidence, time, blocking status | A clean verdict is stale after relevant head update |
| `PolicySnapshot` | max iterations, monetary and token caps, approved actions | Frozen for an in-flight command and versioned |
| `UsageEntry` | invocation ID, provider/model, input/output tokens, measured cost, reservation | Correlate with PR/cycle, no duplicate charges on retries |
| `WebhookDelivery` | delivery ID, event type, installation, payload hash, received/processed status | Unique GitHub delivery identity; bounded retention |
| `OutboxCommand` | command key, payload reference, target, attempt/status | Idempotent dispatch with bounded retry and alerting |

## Review states (suggested)

`NEW` → `WAITING_FOR_REVIEW` → `REVIEWING` → `ACTION_REQUIRED` → `WAITING_FOR_FIX` → `REVIEWING`; clean findings progress to `DEEP_REVIEW`, then `READY_FOR_HUMAN`. `PAUSED`, `BUDGET_EXHAUSTED`, `FAILED`, `SUPERSEDED` are explicit interrupt states.

A GitHub review event is an **observation**, not a final domain verdict unless parsed and correlated. Comments generated by the orchestrator itself must not trigger endless re-reviews.

## Finding correlation

- Inline review thread: track GitHub thread/review/comment IDs and latest diffs, with line path as evidence not identity.
- General review / issue comment: assign a local finding ID; accept explicit human disposition or model-proposed mapping checked against new evidence.
- A single push may address many findings; a single finding may require multiple commits.
- Re-review checks latest head and all pending blocking findings; do not auto-resolve comments based on semantic guesses alone.
